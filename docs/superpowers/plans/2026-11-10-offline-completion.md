# Offline Complete 实施与跟踪计划

> 按任务维护状态和验证证据。每个里程碑开始前补充可执行的子计划，明确模块接口和测试；未验证的设计选择不当成既定事实。

**目标：** 构建独立、离线的 macOS 终端补全应用，首选 iTerm2 + zsh，兼容 macOS Terminal。

**架构：** 以 Amazon Q 开源实现的行为、规则格式和终端会话边界为参考，用 Go 重写离线核心（PTY 会话、shell 集成、IPC、解析、规则、候选、排序与学习）。不迁入 `figterm` 的 Rust 主循环，也不保留其认证、网络、更新和遥测路径。会话代理通过受保护的本地 IPC 与候选窗口、规则核心通信；规则及学习数据存放本地。macOS 候选窗口若必须使用 AppKit，仅窗口层可用 Swift/Objective-C，核心保持 Go。

**技术基线：** Go 1.27.3（`go.mod` 固定版本，由 `g` 管理在 `~/.g/go`）、macOS、zsh；依赖用 `vendor/` 固定，构建使用 `-mod=vendor`，`GOPROXY=off` 可复现。PTY 使用 `github.com/creack/pty` v1.1.24（MIT），本地盘点使用 `golang.org/x/sys` v0.38.0（BSD 3-Clause，另有专利授权声明）。不再使用 Rust、Cargo 或 Node 作为实现或工具链；桌面窗口实现方式待 M0 验证，允许 AppKit/Swift 作为唯一的平台窗口例外。

**设计依据：** `docs/design.md`；调查记录：`docs/feasibility.md`。

## 跟踪规则

- `[ ]` 表示未完成，`[x]` 表示已完成；进行中或受阻时在任务下记录日期、原因和下一步，不以勾选表示部分完成。
- 完成时记录交付文件、验证命令与结果；人工验证记录系统版本、终端、shell、操作和观察结果。
- 功能任务先写能复现需求的测试，确认失败后实现，再运行相关测试和全量测试；手工验收不能替代可自动化的测试。全量命令为 `make test`（自动使用 `g` 管理的 Go 并启用 vendor）；等价的直接命令是 `GOFLAGS=-mod=vendor GOPROXY=off go test ./...`。构建用 `make build`，静态检查用 `make vet`。
- 完成单项不代表里程碑或产品可发布；里程碑必须满足其出口条件。
- 当前工作树尚无提交；保留已有文件和用户改动，不隐含提交、推送或修改现有 Kiro 配置。

## 全局约束

- 首次启动、日常运行、学习和配置均不需要互联网；不发送遥测，不自动更新。
- 不执行未经审查的通用 JS 规则或任意 shell 命令；不回退到远程规则。
- 首先支持 Apple Silicon、iTerm2 + zsh，并验证 macOS Terminal；保留 Intel 构建能力。最低 macOS 版本待验证。
- 不删除或覆盖现有 Kiro 配置；同一个 shell 只能有一个补全接管者。
- 不持久化完整命令、参数值、路径、环境变量或密码；用户可关闭、查看、删除和撤销学习数据。
- 本机提取不等于允许重新分发；许可不明的规则与资源不得进入发布包。
