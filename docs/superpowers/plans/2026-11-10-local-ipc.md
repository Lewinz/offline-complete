# 本地 IPC 设计与实施计划

日期：2026-11-10。依据 `docs/design.md` 第 4、8、9 节及总计划 T08；本文件是设计，不表示 IPC 已实现或安全性已验证。

**实现状态（2026-11-10）：** `internal/ipc` 已实现有界分帧、握手 JSON 校验、随机会话 ID、macOS `LOCAL_PEERCRED` 双向 UID 校验及真实 Unix 连接握手。`PrivateListener` 可在预先存在的私有基础目录下创建并清理会话 socket；其路径检查与使用之间存在同 UID 并发替换窗口，且尚未接入生产事件循环，不视为完成安全清理。跨用户及 Intel 真机行为待验证。

## 边界与选择

采用每个会话单独的 Unix domain stream socket，不监听 TCP/UDP；拒绝系统临时目录中的共享路径。由会话所有者在当前用户私有应用数据目录内建立权限为 0700 的唯一随机会话目录，socket 文件权限为 0600。创建目录时独占创建，不跟随符号链接；检查每一级受控目录的所有者与权限，不接受非目录、符号链接或其他用户可写目录。socket 路径过长则明确失败，不切换到不安全的位置。socket 不承载认证秘密、完整输入或候选值的日志。

macOS 连接时使用 `getpeereid` 检查对端有效用户 ID 等于当前用户；不能获取凭据或校验失败时关闭连接。文件权限和同 UID 校验隔离其他本地用户，但不防御同一用户的恶意进程；随机会话目录仅用于区分会话，不能作为强认证。若要求隔离同一用户的进程，须另行设计并验证平台身份验证，不声称现有方案足够。客户端连接后同样检查服务端 UID。会话 ID 由操作系统安全随机源生成，通信消息携带此 ID 以拒绝误连其他会话；不可作为凭据使用。

消息采用四字节无符号大端长度前缀和 UTF-8 JSON，长度上限 64 KiB（不含前缀）；接收端在分配或读取正文前检查长度，拒绝零长度、超限、无效 UTF-8、损坏 JSON、未知字段与未知版本。首条消息是包含协议版本和会话 ID 的握手；不匹配即关闭连接。具体业务消息待 T09/T13 按最小必要原则定义，不预先传输工作目录或完整命令。分帧读写必须处理短读短写和 EOF，不能在半帧上无限阻塞；连接有超时和有界缓冲。

默认补全不可用，IPC 故障不终止 PTY 或阻塞输入。断连丢弃未完成消息及旧请求，重连重新握手并重新同步当前内存状态；所有插入请求需要独立验证会话、焦点和上下文版本。单个客户端错误不能终止监听器；限流和连接上限防止占满资源。

进程只清理自己创建的会话目录和 socket：清理前比较记录的设备号、inode、类型和所有者；不递归删除目录，不删除替换后的路径。崩溃遗留对象默认不自动删除；可安全识别的过期目录回收须单独设计并测试，无法证明归属时保留并报告，不覆盖已有 socket。目录随机化允许重启创建新会话而不依赖清理旧路径。
